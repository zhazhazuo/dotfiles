# Skill Writing Rules

Write the root `SKILL.md` as a clean instruction list.

Keep in the root file:

- purpose
- when to use
- short process steps
- progressive disclosure rule
- essential constraints

Move out of the root file:

- long examples
- detailed procedures
- variant-specific instructions
- heavy reference material
- long explanations of why the rules exist

Writing rules:

- prefer direct instructions over explanation
- make each step actionable
- keep examples short
- use reference files for details that are not needed every time
- avoid repeating the same guidance in multiple files

Progressive disclosure rules:

- create one reference file per topic
- keep reference files narrowly scoped
- link to the exact file a user of the skill should read next
- avoid deep nesting under `references/`
