# One-Pager Template

Use when Gate 1 fails because the one-pager is missing, too long, or padded. Draft it with the user, not for them — every field must reflect their intent. Exactly one page; anything that does not fit is out of scope or must replace something already on the page.

````markdown
# <Product name>

## North star
One sentence: what this is and why it must exist.

## Problem
Who hurts, and how the current alternatives fail them.

## Product
What the user gets and does. Precise — no adjectives doing the work of decisions.

## The defining constraint
The one rule the product obeys everywhere, front and centre. (Minecraft: everything is blocks. IKEA: flat-pack self-assembly.) State the decisions it makes for you.

## Core tech
The reusable method, tool, or library this build produces, and why it survives the product pivoting.

## Out of scope
What this is not. Contention points end here: if it is not on this page, it is not in the product.
````

Rules:

- If it cannot be filled without fluff, the idea is not ready: research, plan, prototype, then write it again.
- If it needs more than one page, it is too complex: trim or split.
- Keep it current: amend it explicitly when scope changes; never let drift accumulate outside it.
